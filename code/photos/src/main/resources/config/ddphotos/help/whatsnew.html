What's New?

Version 1.0.8 - TBD
  • The album list on the Config tab no longer stretches to fit the longest album name. Names past a set width are shortened with an ellipsis, so a site with a long album title leaves room for the album settings beside it. The list still narrows to fit when every name is short, and the full name is always there in the album details to its right.
Version 1.0.7 - August 26th, 2026
  • DD Photos now looks for a newer release when it starts, and tells you when one is out, with a link to the download instructions. Nothing is installed for you - the notice points you at the installers, and installing over an existing copy leaves your sites, photos and settings alone.
  • You are told once per release. Once the notice for a version has been shown it stays quiet until the next release, whether you upgrade, so it never becomes something to click past at every launch.
  • The check is silent when it fails. Being offline, behind a firewall, or hitting a GitHub outage produces no dialog at all, and the check runs in the background, so it never holds up the app opening. The setup wizard is left alone entirely - the check happens only once you reach the main screen.
  • A new Check for Updates... item under the Help menu asks on demand, and always answers: a newer version is out, you are up to date, or GitHub could not be reached.
Version 1.0.6 - August 25th, 2026
  • DD Photos now notices when a site's albums.yaml is changed by something else while the app is open - a text editor, a script, or an AI assistant - and reloads it, so what you see on the Config tab is what is actually on disk. Previously the app held its own copy for as long as the site was selected, and the next Save quietly wrote over whatever the other program had done.
  • If you are part-way through an edit with unsaved changes when that happens, DD Photos asks whether to discard them and load the new version, or carry on editing. Carrying on means your Save will overwrite the other change, so it checks with you once more before it does.
  • The same goes for the caption (photogen.txt), Custom CSS and deployment settings (site.env) editors, which sit open holding a file for as long as you leave them. In the caption editor each folder is handled on its own, so a change to one folder leaves captions you have typed in another alone.
  • The password editor keeps both changes rather than asking: if something else changes a different album's password while the dialog is open, saving no longer undoes it.
  • A file that is only half written when DD Photos looks at it - caught mid-save by another program - is left alone, and picked up on its next write.
  • Reloads, and the answers you give to any of the questions above, are recorded in the log, so there is a record of what happened to a file and why.
Version 1.0.5 - August 19th, 2026
  • The starter site created by ddphotos init is now made of real files on your disk. Its photos land in a sample-photos folder beside config, and the starter albums reach them through a base named sample-base. Previously they pointed inside the Docker image (/ddphotos-init and friends), which DD Photos cannot open, so a brand-new site had no captions to edit and nothing to show in the Cover chooser.
  • The starter site's hero image is now a .jpg in that same folder, so it previews in the Hero Image chooser like any other photo. The old one was a .webp, which Java cannot decode.
  • The placeholder Replace Me album is now Vacation, and the Secret and Empty albums come from sample-photos as well.
  • The guided tour and the Init tab now explain the starter site: where its photos live, what sample-base points at, and that the folder, the base and the three starter albums can all be deleted once you have added your own.
  • Sites created by earlier versions are unaffected - albums still naming the old /ddphotos paths keep working.
Version 1.0.4 - August 17th, 2026
  • Videos are now part of an album. A .mov, .mp4 or .m4v clip sitting alongside your photos gets a row in the caption editor, so it can be captioned and placed in the manual sort order just like a photo.
  • A video can also be an album's Cover: the Cover chooser now lists clips beside the photos in the folder, and photogen covers the album with the clip's poster frame. A site's Hero Image stays photos only, since the hero is a crop that photogen will not do to a video.
  • Java cannot decode video, so a clip shows a "no preview" placeholder rather than a frame, in both the chooser and the caption editor. In the caption editor it carries a tooltip naming the file, as an unreadable photo (e.g. HEIC) already did.
  • The Upgrade tab now refreshes each site folder's copy of the ddphotos script as soon as the upgrade finishes, so it matches the image you just pulled without waiting for the next start of DD Photos. It also catches up sites added from a folder DD Photos never initialized.
  • The deployment help now covers Cloudflare's 25 MiB file size limit, which longer videos can run into - roughly 40 to 120 seconds of footage, depending on how complex it is.
  • Wording throughout the app and the help now says photos and videos wherever both apply.
Version 1.0.3 - August 12th, 2026
  • Picking an album's Cover photo or a site's Hero Image now opens a DD Photos chooser rather than the system file dialog: the folder as a grid of thumbnails, with a large preview of the selected photo beside its dimensions and file size. Double-click a photo to choose it, or a folder to look inside. It opens on the photo already chosen, so you can see what an album has before changing it, and browsing stays within the album's source folder (or the hero's base), so the path it fills in is always one that resolves.
  • The Publish menu is now the Run menu, since it does more than publish. Its two publishing items are unchanged, apart from Settings... being spelled out as Publish Settings....
  • New Run → Photogen... item, on Cmd-G (Ctrl-G on Windows and Linux). It switches to the Photogen tab and clicks Run for you - handy given how often photogen is rerun after editing a site, an album or your captions.
  • New File → New Site... item, on Cmd-N (Ctrl-N on Windows and Linux), for adding a second (or third) site without stepping through the whole setup wizard. It opens on the Create DD Photos Site Folder step, since Docker and the ddphotos script are already sorted out.
  • DD Photos now notices when a site is one you already have. Save in the Add Site and Edit Site dialogs names the site already using those folders instead of adding a duplicate, and the wizard says the same when you point it at a folder that is already in your sites list. The folder name it suggests moves along to my-ddphotos-2, my-ddphotos-3 and so on when the default is taken.
  • The copy of the ddphotos script that ddphotos init leaves in each site folder is now kept up to date with the app's own copy. Previously only the app's copy was refreshed by upgrade, so running ./ddphotos from a site folder quietly used an older image.
  • Starting the setup wizard or New Site... while run, serve or any other command is going now asks to stop it first. The wizard takes the window, and the command tabs with it, so there would be no way left to stop it.
  • File → Reset Preferences now asks first and spells out what it clears - saved ddphotos parameters, window sizes and positions, hidden dialogs, publish settings and the Docker location found during setup, which means the setup wizard runs again next time. Your sites, photos and config files are not touched.
  • On Windows, if Git Bash is moved or uninstalled, DD Photos now sends you back to the setup wizard to find it again, as it already did for Docker and the ddphotos script.
  • Every tab now carries an icon beside its name. A tab running a command shows a green lightning bolt and a ring the rest of the time, so you can see that run or serve is still up, or watch a publish run move from tab to tab. The Config tab runs nothing, so it gets a pencil instead.
  • Menu items now gray out when they can't be used. Rerun Setup Wizard..., Rerun Tour... and the whole Run menu stay out of the way while the setup wizard, the guided tour or a publish run is in progress, rather than interrupting the one you are in the middle of.
  • Fixed the help for an album's Descriptions File, which described it as per-photo captions rather than the per-album descriptions it actually holds.
Version 1.0.2 - August 7th, 2026
  • New Run menu (called Publish at the time) that publishes a site in one go, instead of running each command yourself. Use Run → Publish Settings... to say what publishing this site means: whether it starts with photogen and build, and whether it finishes with deploy or with export followed by wrangler or surge. Each site remembers its own choice, so they can each publish their own way.
  • Run → Publish... then runs those commands one after another, showing you each tab as it goes. Every step uses the settings you last used on its own tab, so set those up there first. If a step fails, publishing stops on that tab so you can see what happened, and you can publish again once it is sorted out.

Version 1.0.0 - August 3rd, 2026
  • DD Photos 1.0.0 - the first full release, and the end of the betas. Thanks to everyone who tried the beta builds and sent feedback!
  • Links to local servers started in Run and Serve consoles now automatically open.
  • The guided tour now hands the commands to you. Instead of the tour pressing Next to run photogen, run, build and serve, it asks you to click the Run button yourself - the button pulses so it is easy to find - and then follows along. If a command fails, the tour waits so you can fix things and try again.
  • While a tour command is running, the tour explains what to watch for and stays out of the way, so you can browse your site in the dev server for as long as you like before clicking Stop to continue.
  • Stop Tour (formerly Cancel) now asks you to confirm, since several steps ask you to click something in the main window, and it was easy to end the tour by accident.
  • After saving site settings, album settings, photo captions or your custom stylesheet, DD Photos reminds you to rerun photogen to see the changes. The reminder has a don't show this again option.
  • The mouse-over help at the bottom of the window is now yellow on gray, so it is easier to notice.
  • The Edit buttons on the Config tab are now labeled Edit Site and Edit Album, making it clear which side you are editing.
  • Photos that can't be previewed in the caption editor (e.g. HEIC files) now show a tooltip naming the file, rather than just an unexplained placeholder.
  • Clearer wording for an album's Slug, described as the album's name as used in URLs.
Version 1.0.0b8 - July 31st, 2026
  • Added editor for a site's custom stylesheet (custom.css), reached from the new Custom CSS... button in the site details on the Config tab. Rules you put there are loaded after the built-in styles, so they override the defaults.
  • Added editor for deployment settings (site.env), reached from the pencil button beside --site-env on the Deploy tab. It edits the file named in that field, or your [config-folder]/site.env when the field is blank, and creates the file if it doesn't exist yet.
  • Both editors open in their own resizable window, showing the full path of the file being edited and a button to reveal its folder in your file manager.
  • Installer downloads now name the platform, e.g. ddphotos_mac_1_0_0b8.dmg.
  • Clearer help text for Wrangler's --project-name and Surge's --domain, which are names you pick rather than ones DD Photos knows.
  • Surge authentication is now checked with surge account whoami, matching current Surge releases.
  • Fixed --domain, --project-name and --aws-profile being too narrow to show a full value.
Version 1.0.0b7 - July 29th, 2026
  • Added editor for photo captions and manual sort order (photogen.txt file).
  • Added editor for site and albums passwords (passwords.yaml file).
  • New albums are now added above the selected album rather than at the end.
  • On macOS, menus are now available from every window (Help, Support and the photo editor), not just the main window.
  • Undo/redo support in text widgets. Edit menu with undo/redo.
  • Only allow single instance to run at a time.
  • Sharpen image rendering.
  • Refreshed app icon, logo and splash screen.
  • Clearer guidance when Docker isn't running on Linux, covering both Docker Desktop and Docker Engine.
  • Deploy prerequisite checks now tell the difference between "not set up yet" and "the check itself failed". A failed check shows what actually happened instead of offering a fix that won't help. Notably, DD Photos no longer offers to create a Cloudflare Pages project that already exists.
  • The command console now reports how long each command took, both when it finishes and when you stop it.
  • Upgrade now stops with "Cannot upgrade since ddphotos serve is currently running" instead of failing partway through. Docker won't remove the old image while a container is still using it.
  • When a file can't be saved, DD Photos now says which file and why (missing folder, permission denied, read-only location) rather than showing a raw error.
  • sites.yaml, albums.yaml, passwords.yaml and photogen.txt are now written atomically, so a save interrupted by a crash or a full disk can't leave a truncated file.
  • Command console no longer shows raw color codes ([31m) in wrangler output.
  • Fixed caret drifting away from the text you're editing in long fields (e.g. photo captions) on scaled displays. DD Photos now uses your system's UI font rather than a bundled one.
  • Fixed window size restoration when a menu is present (Windows/Linux).
  • Fixed issue where window icons weren't used on Linux.
  • Fixed the site folder showing as invalid when editing a site that uses a custom config path.
